# S3 local transaction tests

These are executable synthetic control-flow checks, not deployment qualification.
Run `make test-storage`; bounded race checks cover CAS and exact retry only:
`go test -race ./service -run '^Test(CASRejectsGapAndConcurrentLoser|OccupiedPositionRequiresExactBytesAndPredecessor)$' -count=1 -timeout=90s`.
The [local contract](storage-v1.md) states codecs, barriers and closed defaults.

`python3 .github/scripts/check-s3-controls.py` runs a green unchanged control and
isolated source overlays for all thirteen mutants above. Each mutant must exit1 at the
named test assertion. Compilation, setup failures, timeouts and missing assertion
text are survivors. The recursion mutant removes both bounded reservation-entry
guards; it does not cover all conceivable recursive logging designs. The digest
collision is a private boolean model, not a claimed SHA-256 collision. The barrier
harness injects calls on an isolated filesystem fixture, never host/device faults.
No power-loss, controller-cache, filesystem-recovery or distributed-exclusion
qualification follows from green tests. No surviving mutant is claimed covered.

## PENDING qualification specifications

The reporter inventories these documentation rows. They are not skipped tests,
executable green placeholders or qualification claims.

`TestWindowRealTimeQualification` is a separately selectable harness, owned
jointly by the Keymaker owners and an independent qualifier. Its qualification
row remains PENDING until they select and qualify the exact tuple; no runner or
tuple is selected here.
Run only for that qualification:
`go test -mod=readonly -tags='swarma_timeconf_fixture swarma_timeconf_qualification' ./internal/qualifiedtime -run '^TestWindowRealTimeQualification$' -count=1 -timeout=60s -v`.
It uses the same settlement/IO, endpoint assertions and unchanged 300/400 ms
budgets with real elapsed time. The endpoint/fence/final clock remain synthetic;
this is not native endpoint qualification. Hosted CI instead checks decision
logic and ordering with `testing/synctest`, real settlement/IO and the same
constants/assertions. Those virtual-time results do not prove the real-time
bound or satisfy this qualification row.

`TestWindowWorkerLifecycle` pairs real settlement bubble exit with cooperative
refusal/Fatal drain controls. A bubble returns only when all its goroutines have
exited, including the private broker worker. A deliberately noncancellable
sleeping worker is isolated in a re-executed test binary; the parent requires its
named failure and synctest deadlock report, never a pass. The 2 s child/3 s parent
limits bound this harness, not a product deadline. Unexpected timeout kills fail
the parent and are reported explicitly. These controls establish no broker-owned
completion/drain API and do not qualify termination of native IO.
The G16 checker also plants a passing child and an unrelated child failure;
`TestWindowWorkerLifecycle/stuck-child` must reject both at its named detector
assertion, rather than counting either as an exercised stuck-worker control.

The new custodian rows specify the [G17/G18/G19 proposal](custodian-v1.md).
All listed controls are future requirements, **not executed mutants or native
qualification**. Valid positive controls must fail under blanket denial, so an
implementation that rejects everything cannot satisfy these requirements.
Neither the second-witness placement nor an arithmetic budget fit closes a gate.
